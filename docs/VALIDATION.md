## 실제 Pi에서 확인한 것

기존 Python 실행 환경을 사용해 임시 디렉터리에서만 실행했다. 의존성 설치, OS·네트워크·기존 서비스
설정 변경은 하지 않았다. 서명 개인키는 노트북에만 두고 공개키만 Pi에 전달했다.

1. 실제 Wi-Fi HTTP 다운로드로 `1.0.0`을 A에 설치·확정.
2. 잘못된 설정의 후보는 앱 초기화에 실패하고 A로 복구. 하한은 그대로 유지, 종료 코드 2.
3. 정상 `1.2.0`을 B에 설치·확정하고 하한 2로 상승.
4. 보안 버전 1인 예전 패키지는 거부.
5. 최종 수정 코드로 다시 실패 후보를 적용해 B의 `1.2.0`으로 복구하는 것을 확인.
6. 기존 `digital-dash.service`는 시험 후에도 active.

이는 새 예제 앱의 **격리된 로컬 모드** 검증이다. 실제 systemd 슬롯 전환, 물리 전원 차단,
CAN 송수신, Qt 표시, 독립 검증 Pi의 보안 판정을 완료했다는 뜻은 아니다.

## 검토에서 발견하고 수정한 문제

- 확정 파일 교체 후 오류가 보고되면 이전 메모리 상태로 복구할 위험: 디스크 저널을 다시 읽는다.
- 첫 슬롯 이동 중 중단되면 초기화 상태를 잃을 위험: 슬롯 변경 전에 빈 저널과 공개키를 저장한다.
- 제한적인 umask에서 앱 사용자가 경로에 접근하지 못할 위험: 앱 디렉터리 권한을 명시한다.
- 첫 systemd 시험 중단 후 후보 서비스가 계속 실행될 위험: 정지 성공 후에만 선택자를 제거한다.
- 확정 SVN과 모순되는 낮은 하한을 허용할 위험: 저널의 두 값이 일치해야 한다.
- HTTP가 조금씩 응답하면 시간 제한을 피할 위험: 헤더·본문 전체에 Linux 메인 스레드 타이머를 적용한다.

## 구현 중 내린 결정과 비용

- 기존 dirty 작업 공간 대신 새 worktree를 사용했다. 비용: 미커밋 프로토타입은 새 기본 경로에 포함하지 않는다.
- worktree 도구 발견과 수동 생성이 겹쳤지만 이미 생성된 공간을 유지했다. 비용: UI 관리 대신 파일시스템 관리 작업 공간이다.
- 기존 코드를 삭제하지 않고 archive했다. 비용: 과거 실행 절차는 기준 커밋의 별도 checkout에서 재현해야 한다.
- Git 작성자 정보는 기존 이력의 `jsy202`를 커밋 명령에만 적용했다. 전역 설정은 변경하지 않았다.
- 로컬 모드는 초기화만 시험하고 상시 프로세스는 선택적 systemd로 관리한다. 비용: 로컬 앱은 직접 시작·종료한다.
- 부팅 시 자동 복구 서비스를 추가하지 않았다. 비용: 선택적 서비스는 재부팅 후 먼저 `ota update`로 복구하고 시작한다.
- 관리자 설치 절차의 초기화 검사는 관리자 권한임을 중요 운영 정보로 판단해 명시했다.
  비용: 서비스 사용자·샌드박스와 같은 보호를 초기화 검사에 제공하지 않는다.
- 실제 systemd·전원 차단 검증은 별도 작업으로 남겼다. 비용: 자동 시험·로컬 Pi 시험으로 양산 수준 복구를 주장할 수 없다.
- 관리자·전체 디스크·적대적 로컬 파일 경합은 위협 모델에서 제외했다. 비용: 하드웨어 보안 저장소 수준의 보호가 아니다.
- CAN·Qt·다중 ECU 기능은 새 기본 경로에서 제외했다. 비용: 후속 호환성 작업이 필요하다.
- 악의적인 서명자가 만든 특수 tar 헤더의 엄격한 메모리 제한은 추가하지 않았다.
  비용: 서명 권한 탈취까지 가정하면 자원 고갈 방어가 충분하지 않다.
- 보존된 과거 구현의 실행을 archive 후 다시 검토하지 않았다. 비용: archive는 지원되는 병렬 설치가 아니다.

중요 검토 사항은 수정했다. 별도로 미룬 경미한 코드 수정 사항은 없다.
