# 알려진 한계와 미해결 문제

README에서 옮겨 온 목록이다. 주장의 범위를 정하는 문서이므로, README의 결과 표나 시연 설명을 인용할 때는 이 문서도 함께 본다.
마지막 갱신: 2026-11-23.

## 미해결 (원인을 모름)

| 문제 | 상태 |
|---|---|
| 일부 실행에서 **지도를 열기 전부터** 처리 지연이 100ms를 넘었다. 2026-11-23 실보드 시연 5회 중 4회에서 관측(기록은 로컬 `.demo/`에만 있고 저장소에는 없음). | 시연이 끝난 뒤에는 남은 워커도 지도 표시 파일도 없었고 세 보드의 CPU도 한가했다. 지연이 높았던 순간의 상태를 잡지 못해 원인을 모른다. 다음 단계는 지도를 늦게 열면서 Pi2의 CPU 사용을 3초마다 기록하는 진단 시연이다. |

이 문제가 풀리기 전에는 "지도를 열자 지연이 생겼다"는 시연 설명이 완전히 뒷받침되지 않는다.

## 시연 절차에서 알려진 위험

- 지도를 V3의 시험 시간(120초) 안에 열지 못하면 Pi3가 정상으로만 보고 **V3가 확정**된다. 확정된 버전은 되돌릴 수 없어, 더 높은 보안 버전 번호로 새 기준선을 올려야 한다(`bench.ivi_rebaseline`).
- 시연을 중간에 끊으면 Pi2가 시험 중인 채로 남아 확정되거나 `recovery_failed`가 될 수 있다.
- 지도 자동 클릭(`--map-trigger pointer`)을 V3 화면 확인 뒤에 누르도록 고쳤지만, **고친 뒤의 경로는 보드에서 처음부터 끝까지 확인하지 못했다.**
- 현장 시연에서는 롤백 뒤 복구된 V2를 다시 감시하지 않는다(2026-11-23 제거). 롤백이 끝난 것과 복구된 이미지가 정상이라는 것은 별개이며, 이 시연은 후자를 확인하지 않는다. 장치의 `recheck` 기능과 시험은 그대로 있다.
- 노트북 한 대로 돌리는 `demo.incident_drill`은 V3 실패 판정을 강제한다. 관제 화면의 안내 줄은 요청에 따라 없앴다.

## 검증 범위

- 부하는 실시간 우선순위 반복 계산을 쓴 **인위적 시험**이다. 실제 IVI의 부하 특성은 검증하지 않았다.
- 주행 입력은 합성 데이터이며 장시간 사용·실차 내구·전원 차단 복구 시험을 대신하지 않는다.
- 실보드 시연은 각 1회씩이며 반복 측정이 아니다. 2026-11-05 결과 표도 1회 실행이다.
- 시나리오 2에서 관제 서버가 꺼진 경우(`maintenance_required`)는 실보드에서 실행하지 않았다.
- 보드 전원·열 제한 이력이 결과 문서에 기록돼 있으며, 결과는 그 환경에서의 값이다.
- Pi2→Pi3 검증 결과를 CAN으로 인증해 전달하는 기능은 가상 CAN(`vcan0`) 시험만 했고 실보드에는 배포하지 않았다.
- 건너뛰는 시험 35개는 실보드 전용, 컴파일된 Qt 앱이 필요한 것, `vcan0`가 필요한 것이다. CI는 Qt·vcan 시험이 건너뛰어지지 않게 감시한다.

## 동작상 예외

- 정차 대기가 `max_wait_s`(기본 600초)를 넘거나 Pi3 관측이 끊기면 축소된 판단으로 롤백한다. **"항상 정차 후에만 롤백한다"고 말할 수 없다.**
- Pi3 감시기는 재부팅 후 자동 시작 설정과 listen-only 하드웨어 모드가 없다.

## 구현하지 않은 것 / 범위 밖

- 서명된 자원 계약, 설치 전 정적 자원 호환성 검사는 설계만 있고 구현하지 않았다.
- 다운그레이드 방어 자체(부팅 전 검사, 기준값의 외부 보관)는 강화하지 않았다.
- 악성 클러스터의 허위 응답 방어는 구현하지 않았다. 측정 대상은 클러스터 소프트웨어의 처리 응답 지연이며 화면 픽셀이 그려진 시간이 아니다.
- OS OTA, 독립 광학 검증, 관리자 권한으로 신뢰 기록까지 변조하는 공격 방어는 범위 밖이다.

## 저장소 정리 대상

- 일부 문서와 코드에 `/home/<사용자>` 경로가 남아 있고, 추적되는 `.planning/` 폴더가 있다(비밀번호·개인키는 검토에서 발견되지 않았다). 정리하려면 이력까지 건드려야 한다.

## 보안 주의

HTTP 전송은 실험망 용도이며 암호화·접속 인증을 제공하지 않는다. 개인키·SSH 키·Wi-Fi 비밀번호를 Git이나 릴리스 제공 폴더에 넣지 않는다.
