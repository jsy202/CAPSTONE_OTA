    Data ID는 무엇이고, CAN 메시지 번호와 다른가요?

    CAN 번호 0x200은 버스에서 메시지를 구분하는 번호입니다. Data ID 0x21은 송신·수신 쪽이 같은 값을 알고 있어야 하는 보호 설정입니다. 이번 구현은 Data ID를 메시지에 별도로 싣지 않고, 내용의 검삿값인 CRC 계산에 포함합니다. 양쪽 설정이 다르면 같은 내용을 받아도 검사가 실패합니다. 0x21·0x22는 사람이 보기 위한 16진수 표기입니다.

    검증기가 화면에 뜬 속도를 직접 보는 건가요?

    아닙니다. 지금은 CAN 메시지와 Cluster가 보고한 내부 처리 값을 비교합니다. 화면을 촬영하거나 Qt 렌더링 결과를 읽지 않습니다. 따라서 입력 생성과 판정은 분리됐지만, 출력의 진실성은 Cluster 보고에 의존한다는 한계가 있습니다.

    V1을 한 번도 실행한 적 없는 차량도 막을 수 있나요?

    가능합니다. 이 시연은 V2에서 바로 시작합니다. V1 사용 이력이 아니라, 신뢰하는 V2의 정확한 파일 지문과 설치 시 확정한 보안 기준을 사용합니다. 다만 공격자가 그 기준 기록까지 바꾸는 상황은 방어 범위 밖입니다.

    V1을 막으면 정상 서비스가 자동으로 복원되나요?

    아닙니다. 온전한 V2가 있으면 정상 롤백을 지원하지만, 복구할 파일이 바뀌어 차단된 경우에는 복구 실패로 남습니다. 취약한 V1 실행 차단과 서비스 가용성 복원은 별개이며, 차단 뒤 재다운로드·정비 복구는 이번에 구현하지 않았습니다. “차량이 안전하게 정상 운행한다”고 주장하지 않습니다.

    이게 실제 자동차에서 쓰는 방식과 같나요?

    AUTOSAR E2E에는 송수신 Data ID와 CRC를 사용해 통신 오류를 검출하는 원리가 있습니다. 이 프로젝트는 그 원리를 단순화한 Data-ID 결합 CRC-8 시험이며, 정식 AUTOSAR 프로파일 구현은 아닙니다. 잘못된 통신 설정을 한쪽 ECU에만 배포하는 상황도 설계한 가정이며, 특정 양산 차량의 실제 사고 사례를 재현했다고 주장하지 않습니다.

    CRC와 시험 번호가 해커의 메시지 위조도 막나요?

    아닙니다. CRC는 오류 검출용이고, 시험마다 바뀌는 번호는 응답을 해당 시험과 연결하는 용도입니다. CAN 송신자를 인증하지는 않습니다. 이 시험은 고정 Cluster·검증기·SSH 신원을 신뢰하는 격리된 시험대를 전제로 합니다.

    기존 가상 시연과 새 세 Pi 구현은 무엇이 다른가요?

    기존 demo.run은 한 장치에서 별도 프로세스로 재연결 후 순서 번호 초기화 결함과 V1 바꿔치기를 재현합니다. 새 demo.can_bench는 세 호스트가 CAN·SSH로 연결되는 실행 경로이며 Data ID 설정 불일치를 사용합니다. 이 자료의 공격 단계는 기존 구현의 방어 원리를 통합 흐름으로 설명하며, 실제 세 장치 공격 시험 결과가 아닙니다.
