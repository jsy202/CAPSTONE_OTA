# Qt Cluster end-to-end verification

User authorized complete PC implementation and fault injection without intermediate
approval. Continue existing isolated feature worktree; preserve Downloads originals.

Build the pinned Volvo Qt dashboard with a small CAPSTONE entry point, retaining its
real C++ gauge models/QML. Feed classic 0x200 vehicle frames through SocketCAN on
hardware or explicit loopback UDP emulation on PC. A restricted local socket reports
actual gauge and QML-bound values, validity, receive generation and process identity.
It does not claim independent pixel evidence. The Qt runtime stays outside signed
application slots; executable/config/QML resources are immutable inside slots.

Version combination: legacy buffered Central can replay delayed samples after link
recovery. Cluster V2 checks source counters and rejects older samples. Cluster V3
optimizes for a latest-only Central and trusts arrival order. V3 with latest-only
Central works, but V3 with buffered Central displays old speed between current ones.
These are declared bench contracts, not an OEM incident or native CAN replay feature.
Do not inject fabricated wrong speed or forced FAIL into the candidate.

An external verifier owns input traces, injects disconnection, delays/replays, counter
wrap and repeated recovery cycles, and samples the real Qt model/QML binding after
each delivered frame. It uses literal expected latest values, not candidate decoding.
Normal, compatible and mixed combinations run before real signed two-hop OTA tests.
Failed Cluster V3 trial must return to V2 and re-run the same verification. A genuine
signed V1 substituted for V2 is refused before execution. No automatic restoration
after refusal, OS update or week-long reliability claim is added.

a self-contained local orchestrator. Local control transport may be substituted for
